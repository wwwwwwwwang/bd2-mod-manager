### 修掉的一个真 bug

首轮卸载后残留 `BepInEx\`、`BepInEx\plugins\`、`BepInEx\Translation\ar\` 等空目录。

原因：`Directory.CreateDirectory(叶子目录)` 会连带创建所有父目录，但状态文件只记录了 manifest 里的叶子目录，
中间层没记录 → 卸载时漏删。

修复：新增 `EnsureDir()`，逐级创建并记录**每一层**新建的目录；卸载时按深度倒序删除。
另外补了 `PruneEmptyBaseDirs()`，顺手清掉自己建的空状态目录。

## 六、图形界面（0.2.0）

Linux 上开不了 Windows 窗口，就用 Xvfb + scrot 把 Avalonia 界面真跑起来核对，再用 xdotool 模拟点击，把「装 → 卸」整条链路走完（远端目录 `ssh.build-host.example:~/build/bd2mm`，假游戏目录 `/tmp/fakegame`）。

| 步骤 | 结果 |
|---|---|
| 启动自动探测 | 显示路径、Unity 版本、状态「未启用 / 游戏目录干净」 |
| 点主开关 | 用**内嵌**的 loader 包安装成功：新增 54 个文件，状态转「已启用 BepInEx 5.4.23.6 · Doorstop 4.6.0 · 本工具安装」 |
| 插件区 | ConfigurationManager.dll 被识别为 1 个插件，行内开关可用 |
| 再点主开关 | 弹确认框；确认后逐项删除空目录，游戏目录回到只剩 `BrownDust II.exe` / `BrownDust II_Data` |
| single-file 发布（linux-x64 自包含 + 内嵌资源） | 正常启动、正常安装，内嵌包在单文件模式下可读 |

顺手修掉的两个问题：

- `BepInEx.dll` 的 ProductVersion 带提交哈希（`5.4.23.5+57f1fb85…`），界面与 CLI 都整串显示 → 统一截到 `+` 之前。
- `bd2mm.exe` 双击「一闪而过」：其实是无参数打印帮助后正常退出。现在检测到交互式控制台会等待按键，且帮助里指向图形界面版。

win-x64 发布体积：未压缩 92 MB，开 `EnableCompressionInSingleFile` 后 45 MB。
